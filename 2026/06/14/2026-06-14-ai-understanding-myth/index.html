AI其实根本不懂你在说什么

最近看到一段关于某个程序员对 AI 和大模型理解的采访，发现很多人对大模型的基本工作原理也是一知半解。我就在想怎么能简单直白地把这个问题讲明白，让非专业人士也能一听就懂。

比如你手机上的豆包、DeepSeek 或者元宝，这些 AI 助手你可能都用过——应该有过这种感觉——它好像真的”懂”了。你问它一个问题，它给你一段有条有理的回答，像极了一个聪明的人类。其实真实情况是它压根不懂：它只是太会猜了。 接下来我就把关于大模型和 AI 的几个基本概念给大家捋一捋。

一、猜词机器——大模型的核心秘密

大模型从出生到长大，只学了一件事：猜下一个词。

举个例子。你输入”中国的首都是”，模型内部算一个概率表：

  • “北京” → 98.7%
  • “上海” → 0.3%
  • “东京” → 0.1%

选最高的那个，输出。然后继续猜下一个。

graph LR
    A["用户输入: 中国的首都是"] --> B["模型算概率"]
    B --> C["北京: 98.7%"]
    B --> D["上海: 0.3%"]
    B --> E["东京: 0.1%"]
    C --> F["选最高概率的"]
    F --> G["输出, 继续猜下一个词"]

整个对话，都是这样一句一句”猜”出来的。没有思考，没有意识。

你可能想问：凭什么猜这么准？

答案有点无聊：它读完了整个互联网。 维基百科、几亿本书、论坛帖子、GitHub 代码、论文新闻……总量是几万亿个小片段（专业术语叫 token，把一段文字拆成更小单元，可能是一个词的一部分、一个完整的词、或者一个标点符号）。

graph TD
    D1["维基百科"] --> T["切碎成token"]
    D2["书籍"] --> T
    D3["论坛/代码/新闻"] --> T
    T --> M["训练: 猜下一个词"]
    M --> R1["学会语法"]
    M --> R2["记住事实"]
    M --> R3["学会推理"]

你打一句”中国的首都是”，它在训练数据里见过几百万次。不是在理解你，而是在统计上记住了：这句话后面，大概率跟着”北京”。

所以有个很反直觉的事实：它只是概率算得好，不是真的会思考。

我给朋友解释的时候用三个比喻：

超级填字游戏选手——给你不完整的一句话，填上最合适的下一个字。区别是你填字靠智商，它靠见过几万亿句。

读过全网的模仿大师——它不”理解”光合作用，但它见过这个词在几十万种上下文里出现的样子，所以能装得很懂。

靠刷题上岸的学生——先广泛阅读，再背标准答案（按模板学），最后反复刷模拟题看打分，琢磨出老师喜欢的答题风格（人工打分教出来的）。

二、从”续写机器”到”对话助手”

预训练完的模型，本质上就是个文本续写器。给它一个开头，它能往下编，但没法好好回答问题。

要让它会聊天，还得再走两步。

第一步：背标准答案（按模板学）

找一堆人来写问答对。比如”用大白话解释黑洞”→”黑洞就是引力特别强、连光都跑不出来的区域”。几万条这样的数据让模型照着学，它慢慢就懂了：用户提问的时候，我应该输出答案，而不是继续往下编故事。

第二步：让人来给答案打分、教模型学习好坏

这一步才是真正下功夫的地方。比如让 AI 写请假邮件，它可能写出好几个不同的版本：

版本 A 的请假邮件写得正式得体，版本 B 吊儿郎当，版本 C 语气不对。标注员按”有帮助、诚实、无害”排个序，然后用这个数据训练一个打分器。最后用这个打分器来训练模型——得分高的回答就学，得分低的就改，反复来回调整。

graph LR
    S1["AI写多个版本"] --> S2["人工排序: A>B>C"]
    S2 --> S3["训练打分器"]
    S3 --> S4["用打分器训练模型"]

ChatGPT 和 Claude 那些让你觉得舒服的特质——回答有条理、语气温和、知道什么时候说”我不确定”——大部分就是这么磨出来的。这一步背后是大量标注员人工喂给 AI 的。

三、AI 产品又在大模型外面干了什么

很多人以为大模型就是 AI 产品本身。其实模型只是一台文本生成引擎，你感受到的那些”智能体验”，是好几层工程堆出来的。

偷偷塞纸条（系统提示）：你提问之前，AI 产品先偷偷给模型塞一段话。比如你跟 ChatGPT 对话，ChatGPT 会先给大模型一段提示词”你叫 Claude，你是 Anthropic 开发的，知识截止于 2025 年，用中文回答”。你看不到这段话，但它决定了整个对话的画风。

加道安检（安全过滤）：大模型输出到你眼前之前，过了好几道关——暴力词过滤、分类器判断、规则引擎兜底。

帮你查资料（RAG）：大模型知识是有截止日期的。你问”今天天气怎么样”，AI 产品先调 API 拿到数据，再塞给模型。所以它能答出来——不是它知道，是有人替它查了。

边写边发（流式输出）：你发出去不到一秒就看到回答在”打字”。这是工程优化的功劳，不是模型反应快。

翻译官（多模态）：图片、语音、文件——这些都不是模型天生能处理的。图片要切成小块编码，语音要转成文字，PDF 要提取文本。产品层帮你搞定了，你才觉得它什么都能读。

四、一个经常被误解的事：工具调用到底是谁在做

很多人觉得”AI 自己会去搜索、会调用工具”。

真相是：大模型不会调用任何工具。它只是在输出文本的时候，学会了一种特殊的格式。

sequenceDiagram
    participant U as 你
    participant A as 产品层
    participant L as 大模型
    participant T as 搜索API
    U->>A: 查航班
    A->>L: 读提示+问题
    Note over L: 决定调什么工具
    L-->>A: 输出function_call
    A->>T: 真的去搜
    T-->>A: 返回结果
    A->>L: 结果塞回上下文
    L-->>A: 生成回答
    A->>U: 展示结果

你搜”北京到上海的航班”，大模型生成的是这样一段文本：

然后它停了。真的去调 API 的，是产品层的代码，不是模型。

为什么非要隔一层？安全。如果模型能直接调 API，你让它”删库”它就真去删了。产品层卡在中间，可以决定”这个操作不允许”。

所以准确的说法是：大模型有”表达调用意图”的能力，Agent 有”真的去执行”的能力。 两个凑一块，看起来就像 AI 会自己查资料。

五、Agent 时代——当 AI 不再只是”说话”

ChatGPT 主要干的事是”问答”。但 Claude Code、Codex、OpenHands 这些，干的事不太一样——它们是”干活”。

区别很直观：

ChatGPT：你问 → 它答 → 你自己动手去做

Agent：你给一个目标 → 它自己拆步骤 → 执行 → 发现问题 → 自己修 → 继续 → 直到干完

要做到这个，需要几个升级：

工具系统——不只是打字，还能读写文件、跑命令、搜代码。

沙箱环境——它在里面真的把代码跑起来，看结果，报错了自己读日志修。

循环推理——干一步看一步的结果，决定下一步干什么，而不是一次生成完拉倒。

任务拆解——你说”帮我写个博客系统”，它自己拆成：创建项目、写数据库、写 API、写前端、写测试，一条一条干。

错误恢复——跑 npm 报错了？自己读日志、改配置、重跑。

六、移动端 + Agent：是噱头还是真有用？

这个问题我自己想过。结论：大部分宣传是噱头，但有四个场景是真的。

为啥说是噱头

PC 端本来就能做的事，非要搬到手机上——为了省那几分钟打开电脑的时间？手机打字慢、屏小，看个报错日志都费劲。

但有些场景是真的

长时间任务监控——训练模型几小时，你总不能坐电脑前等。手机上偶尔看一眼进度就好。

本地算力遥控——这个最硬核。你的电脑有 4090，手机没有。数据在本地不能上传。在外面的时候，让家里的机器帮你跑活。

碎片灵感捕获——半夜突然想到一个 bug 怎么修，手机上说一句，第二天醒来电脑上已经改好了。

不打断当前工作——正在集中精力写代码，不想切窗口。手机上发条指令让 Agent 在后台干。

一句话：想用它替代电脑是扯淡，但当成遥控器加灵感笔记本，挺好用的。

结语

回头看整条链路：读全互联网 → 学会猜词 → 学会回答 → 学会高质量回答 → 产品层包装（系统提示、安全、RAG、流式）→ 工具化 → 自动化循环。

每一步都是工程上的加法。没有哪一步让模型真的”理解”了什么东西。

但它确实从一个只会写字的引擎，变成了能帮你干活、能调试代码、能管理任务的数字同事——就是那种虽然不懂你在干什么，但活儿干得挺利索的同事。

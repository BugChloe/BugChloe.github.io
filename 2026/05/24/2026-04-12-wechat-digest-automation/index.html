一个下午，我把"公众号焦虑"变成了自动日报

引子：几十篇未读，一个都不想点

周日中午，我第 N 次打开微信订阅号列表，看到熟悉的红色小圆点。积压了一周的文章 —— 学习类的、科技资讯类的 —— 密密麻麻排在那里。

我有两个选择：花一小时逐篇翻完，或者像往常一样划掉，假装没看见。

但我选了第三条路。

“能不能写个脚本，每天自动抓文章、让 AI 帮我总结、推到我面前？”

以前这种想法我一般会在心里种下，然后等一个”有空再说”的周末 —— 那个周末永远不来。但这次不太一样。我打开了 Claude Code，打了第一行字。

第 0 步：跟 AI”聊需求”，像跟同事讨论一样

我没有写任何技术文档。我就是把想法直白地告诉了 AI：

“我订阅了一些微信公众号，想每天自动抓取推送的文章，用 AI 做摘要，然后推送到飞书消息。帮我设计一个可行方案。”

AI 没有直接写代码。它先问我几个问题：文章源怎么获取？有现成 RSS 吗？推送方式偏好什么？大模型用哪个？

几个来回之后，完整架构出来了：

选型也很快。WeWe RSS 是一个开源项目，能把微信公众号转成标准 RSS 订阅源，跑在 Docker 里。大模型选了一个兼容 Anthropic 协议的服务，Python 直接用 anthropic SDK 就能调，不用额外适配。推送选飞书消息，因为我的 Lark CLI 已经配好了。

整个过程不到 20 分钟。我没有写一行需求文档，但 AI 已经把架构图画好了。

这个阶段的核心体验是：你不是在”下指令”，你是在”讨论”。AI 提出选项，你做决策。就像跟一个有经验的同事 pair programming，只不过这个同事永远不会累。

第一关：Docker 和 “connection refused”

方案定了，开始动手。

第一件事是拉 Docker 镜像。我装了 OrbStack（比 Docker Desktop 轻量的替代品），AI 告诉我执行 docker pull 就行。

还没等我反应过来，AI 已经判断出是网络问题 —— 国内访问 Docker Hub 经常被墙。它查了我的 OrbStack 配置文件，自动写入了两个国内镜像源：

重启，镜像拉下来了。WeWe RSS 启动成功，浏览器里输入 localhost:4000，看到了 RSS 订阅界面。

这是一个转折点。如果没有 AI 主动排查，我大概率会在这卡半小时 —— 先怀疑自己操作对不对，再搜”Docker 拉镜像失败”，试各种方案，最后可能放弃换方案。但 AI 在我还没开口问的时候，已经把问题定位并修好了。

为什么这个 AI 能”主动排查”？

这里插一句值得说的细节。AI Agent 和传统编程助手（比如代码补全）最大的区别是：它有”工具”。

它可以读你的文件、执行命令、看报错日志、查进程状态。它不是凭空猜问题，而是真的在”debug”：

这个”读 → 判断 → 改 → 验证”的循环，就跟一个工程师的调试流程一模一样。区别只在于它做得快得多。

这些细节如果是我自己写，大概率是”先标记再保存”，等出了 bug 再修。但 AI 在设计阶段就把它做对了。

第三关：”环境异常” —— 微信的反爬城墙

代码写好了，跑一遍试试。

脚本运行，RSS 抓到了 10 篇文章。然后进入正文提取环节。我心里期待看到一大段英文播客对话或者科技文章内容。但实际出来的是：

每一篇都是这样。WeChat 反爬机制启动了 —— 它检测到请求不是来自真实浏览器，直接拦截。

AI 先试了 WeWe RSS 的全文模式（FEED_MODE=fulltext），以为通过微信读书 API 能绕过。不行，还是”环境异常”。

然后试了直接 HTTP 请求原文链接 —— 一样被拦。

这时我有点泄气。这是微信平台级别的防护，如果绕不过去，整个方案就废了一半 —— 只能靠文章标题生成摘要，效果大打折扣。

AI 没有放弃。它做了一次关键的尝试：

重新运行。

命令行里滚出来的不再是”环境异常”，而是真正的文章正文 —— 完整的段落、对话、观点，一字不差地提取出来了。

十几秒后，第一篇摘要也出来了，要点的提炼准确、简洁，完全是我想要的效果。

我当时的感觉很微妙。不是”AI 好厉害”那种感叹，而是一种更实际的感觉 —— 刚才这个坎，如果是自己搞，很可能就卡在这里放弃了。但 AI 扛住了，试了三种方案，最后找到了突破口。

第四关：从邮箱到飞书，说改就改

脚本跑通了，日报保存到了本地文件。下一步是推送。

最初的设计是用飞书邮箱发日报。结果 AI 一查，发现我的飞书账号没开邮箱功能。

放在以前，这个问题意味着要停下来 —— 申请邮箱权限、等审批、再回来继续。少说半天，多则两三天。

AI 提议：”改成飞书消息推送？你的 Lark CLI 本来就支持 IM。”

这种灵活性是我觉得 AI 协作最大的隐性收益。方案不是写死在文档里的，它可以在开发过程中随时根据实际情况调整，调整成本极低。

复盘：3 小时的”想法自由”

下午 2 点开始聊天，5 点多系统跑通。全程大约 3 个多小时。

如果自己从头搞，需要多长时间？

让我算一笔”能力债”：

  • 调研 WeWe RSS 怎么用、怎么配 Docker → 1-2 小时
  • 读大模型 API 文档、搞清楚兼容协议 → 1 小时
  • 读 feedparser / trafilatura 库文档 → 30 分钟
  • 写 Python 脚本 + 调通 → 2-3 小时
  • 遇到反爬问题，查资料、试方案 → 1-3 小时
  • 配 launchd 定时任务 → 30 分钟
  • 调通飞书推送 API → 1 小时

加起来 7-12 小时，还不算中间遇到挫折想放弃的”心理耗时”。

AI 压缩的是什么？ 不是”打字速度”，而是每一次”下一步该做什么”的决策疲劳和认知开销。你不用自己去查文档、不用自己排查报错、不用自己想”这个边界情况怎么处理”—— AI 主动推着你往下走。

这才是 AI 时代最让人兴奋的事情。想法的试错成本被拉到了极低。 一个下午的突发奇想，不用等排期、不用攒精力、不用说服任何人，直接就能变成每天在用的东西。

如果你也有那种”要是有个工具能帮我做 XX 就好了”的念头 —— 不要再等了。也许 3 个小时后，它已经在帮你干活了。
